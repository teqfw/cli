# Environment Configuration

- Path: `ctx/docs/environment/configuration.md`
- Changed: `20260921`

Only the root host package.json may declare host-related settings such as teqfw.fw.cli.container.configurator, relative to the application root. The host's manifest-declared configurator receives applicationRoot and argv and may return JSON-safe `container` policy data: namespace mappings, Dependency Identifier strings for preprocessor, postprocessor, and hardener producers, and diagnostic flags. It may also return additional ordered cfg Source descriptors. Packages may publish compatible configurator contributions for static host import, but never declare host metadata. CLI loads host Sources followed by the application-root `.env` and `process.env` exactly once. A missing default `.env` is ignored; `--dotenv-file <path>` or `--dotenv-file=<path>` selects an explicit path relative to applicationRoot and missing or invalid explicit files fail startup. Host Sources are defaults, dotenv overrides them, and process.env overrides both. The configurator is pre-DI and must not rely on DI or load cfg itself. Runtime-config fields and ordering are defined in [container-configurator.md](../architecture/container-configurator.md) and cannot be overridden by cfg. Namespace paths resolve against their publishing package. Do not log secrets, arbitrary configuration values, or raw command input.

In explicit host selection, the application root is the selected host package root: its configurator, `.env`, and explicit dotenv path apply to that root, while the original working directory is retained as the launch `cwd` fact. Runtime-config and Source ordering do not change.

## Dotenv Ordering

`teq cfg:sort [file]` accepts only a valid dotenv file. With no `file` argument it targets `.env` in applicationRoot; an explicit relative path is resolved from the original cwd. It preserves each assignment's original syntax and value, including `export`, inline comments, duplicate keys, multi-line quoted values, and trailing comments. It classifies only complete cfg keys (`NAMESPACE__PARAMETER`) as described by `@teqfw/cfg`; non-cfg assignments remain before all configuration groups.

The command orders groups by namespace and entries within each group by parameter name. A comment block before the first entry of a namespace is that group's preamble and moves with the group without internal sorting. A comment block before any other entry moves with that entry. The resulting group has no blank lines internally and adjacent configuration groups have exactly one blank line. Comments that do not precede an assignment remain in their original non-assignment area. `--check` reports whether a rewrite would be needed without writing and exits unsuccessfully when one is required; `--dry-run` reports the same pending action successfully without emitting configuration values. A normal run replaces a changed target atomically.
